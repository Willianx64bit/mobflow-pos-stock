## Login diagnosis

The reported login attempt returned the application's generic message: "Usuário ou senha inválido."

Read-only checks against the existing Supabase PDV project confirmed:

- The TESTE.MOBFLOW profile exists.
- Its profile is active and its role is `manager`.
- Its Auth identity exists and its email is confirmed.
- The Auth email matches the deterministic alias generated by the currently deployed `mobflow-login` function.
- The company's subscription is active and its expiration timestamp is still in the future.
- The same profile identity UUID is present in both Neon test branches: `integration-test` and `api-state-validation`.

The deployed Supabase Edge Function `mobflow-login` is version 27. Its `index.ts` content matches the file in this migration branch byte-for-byte.

### What this proves — and what it does not

The failure is **not explained by a missing profile, inactive profile, CNPJ mismatch, missing Auth identity, email-alias mismatch, or inactive/expired subscription**.

The current login function finishes by calling Supabase Auth `signInWithPassword`. The password hash is not readable through the database, so this audit cannot establish whether the attempted password is the current Auth password. The most likely remaining explanation is a password mismatch, but that has not been proven.

No login attempt was replayed against the production Auth service. No password was reset, changed, or exposed. No production row or Auth identity was modified.

## Separation from the Neon API migration

The current browser login remains in `src/components/LoginScreen.tsx` and `src/lib/supabase.ts`, and continues to call the Supabase `mobflow-login` Edge Function.

The new Neon API does **not** issue username/password sessions. It accepts an existing Supabase access token, verifies it against Supabase Auth, then resolves the same user UUID and tenant profile from Neon. This is a temporary identity bridge for the database migration, not an Auth-provider cutover.

Therefore, the reported username/password test is not a valid end-to-end test of the Neon state API. It exercises the existing Supabase login path.
